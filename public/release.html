02 / 本版内容

从标准对齐到修改复查，流程连起来。

  1. 两条 Loop 的完整路径

    标准账本、提案独立审查与冻结；单元拆分、快筛、深核、独立复核、协调和最终处置。

  2. 可信宿主与决定接线

    用实际 hook / rollout 核对子任务身份，收件可使用 assignment_id；原生卡片答案来自真实宿主回执。

  3. 增量复查与恢复

    按材料、标准、来源和依赖计算重查范围，保留历史结果；包括首轮最多三轮，失败与成本均有可见边界。

  4. 本轮修复

    退回标准后必须修改重审；成本和证据过期的恢复路径修正；B1 设计语境澄清；最终卡缩为摘要；对齐结果绑定错误纳入已有技术重试。

  5. Codex 工程适配

    五个 Skills，MCP Runtime，Task State SDK 0.5.0 原字节快照；新状态根 reviewer/v1，旧实现保留于 Git 历史。

04 / 已知边界

本轮通过，不意味着所有场景都通过。

  • 真人体验尚待观察。测试中的卡片答复来自合成客户端；Desktop 重开、真实 Skip、人的阅读与决策体验仍需实际使用验证。
  • 长标识仍可能抄错。两轮曾出现 assignment ID 和 digest 转录错误。现在可拒收并有界恢复；由 Runtime 自动回填属于协议变更，尚未实施。
  • 同一问题可能重复呈现。多个单元和 deep / crosscheck 路径可能报告同一缺陷，增加阅读负担。
  • 其他宿主与多人场景未验收。本轮仅适配 Codex，不把 Claude 参与复核写成 Claude Code 运行适配。
  • 普遍产品效果未证明。三次重复仅用于这次修复验收，不填充历史待定的有效性数字合同。
