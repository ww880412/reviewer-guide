01 / 职责分层

从发起，到可追溯的决定。

点选层级查看职责与边界。这是架构说明，不连接运行中的评审。

↓ 发起任务 / 回答问题卡
↓ Skills 指导 Agent · MCP 承接动作
↓ 可信接线 / 持久化协议
↓ 业务 head + SDK journal

决定层

人保留决定权

你确认标准与评审方案，并决定材料是否接受。超出成本、改变范围或跳过规定检查时，也由你作取舍。

职责边界

Agent 可以提案和解释，但不能把自己的输出写成你的决定；测试客户端答复也不能证明真人验收。

依据：产品设计 §5–6；Reviewer 入口 skill

02 / 两条产品 Loop

标准冻结，检查才开始。

LOOP 1 · 标准

任务 + 已签核来源 + 标准账本

起草 → 新增／冲突项表态 → 构建不可变提案 → 独立覆盖与忠实度审查 → Owner 整体确认 → 冻结并补账

退回就必须修改

审查未过先返修；Owner 退回后也要改提案并重审。不能用 A → B → A 重新提交旧稿，或用旧审查开确认卡。

↓ 冻结标准与检查方案
LOOP 2 · 材料

拆单元 → 快筛 → 深核 → 独立复核

协调发现与分歧 → 形成当前最终页 → 处理必要的标准分叉 → Owner 决定 → 修改后增量复查

独立不是自报字段

Runtime 核对实际子 thread、父会话、任务单、attempt 和输入版本。复核者读取原材料与发现定位，不接受原深核结论理由。

仅对齐模式在 Loop 1 交付标准后结束；后续检查材料需要新建评审并核对适用性。改范围回 Loop 1；同范围的普通复查不重新确认标准。

03 / 检查依据

项目标准 + 五条固定置信规则。

规则 核验什么
CR-1 · 事实 版本、状态、时间、数字、支持关系和归属是否与一手来源一致。
CR-2 · 引用 来源不仅要存在，还要真正支持被引用的那句话。
CR-3 · 不杜撰 不存在查无实据的来源、版本、API、术语和数据。
CR-4 · 强度与地位 “已证明”“唯一”“共识”及自称权威、SSOT 的声明同样接受事实核验。
CR-5 · 前提 未经验证的前提不能以已证实的口吻支撑结论。

防止误报同样重要。内部设计选择按整篇设计语境理解，无须逐句证明已经存在；但“当前已部署”“已经验证”等现状断言仍需核验。历史标签、披露的过时内容和同义术语本身不等于杜撰，允许来源之外也不能自行扩查。

杜撰无论出现在哪里都阻断；其余四类在承载结论的单元上不满足或证据不足时阻断，非承载问题作为修改项。承载性拿不准时按承载处理。

04 / 三条证据路径

身份、输入、决定分别绑定。

路径 如何建立 拒绝什么
子任务结果 assign 发任务单 → 宿主启动独立子任务 → collect 从可信轨迹读取最终结果 错任务、旧 attempt、身份不明、未完成、结果缺项或绑定不匹配
检查输入 冻结材料、标准、方案和单元清单；结果回连对应 digest、原文和允许来源 拿新磁盘内容替代旧快照，或把过期结果挪给新版本
人的决定 Runtime 开 ticket → 原生卡呈现 → 绑定真实 questionItemId → 从宿主回复取答案 Agent 自报答案、缩改题面、旧卡答案挪用、把沉默当同意
结构通过不等于内容为真

SDK 和 Runtime 能检查回执、字段与版本关系；“是否忠实理解标准”“证据是否支持断言”仍属于语义核验，可能产生分歧，也可能出错。

05 / 增量复查

重查影响范围，不只重查改过的段落。

四类变化种子

材料节改动或删除
标准条目变化
证据过期或来源变化
新增单元

→
反向依赖闭包

找出依赖这些变化的单元，再沿依赖继续展开。

→
重查 / 有据沿用

闭包内重新核验；闭包外只有具备版本和新鲜度凭据才能沿用。

例子：引用的服务版本变了，即使方案文字未变，依赖该版本能力的论证和结论也要重查。上一轮接受的检查缺口风险不自动继承。

本轮新结果仅在其声明的 TTL 实际到期时失效；缺少新鲜度字段影响下一轮能否沿用。包括首轮在内最多三轮，第三轮仍有阻断就停止并说明原因。

06 / 执行与恢复

把技术故障和业务问题分开。

事件 当前处理 不代表什么
技术结果无效 拒收并记录失败；第一次可重派一次，第二次耗尽按阶段进入控制或缺口处理 不能靠换提案、换任务名不断清零重试
证据仍有分歧 保留 dissent 和证据不足，按标准判断影响 完成了独立检查不意味着必须强行统一结论
成本达到上限 暂停新派发与新结果采纳，交人选择放行、按现有结果收尾或停止 风险接受不把证据不足变成通过；迟到消耗仍记账
中断 / 进程重启 同 thread 查 status，从业务 head 与 SDK journal 继续 跨 thread 不继承旧决定权限
持久化完成记录失败 达到边界后进入只读并退出，交新进程恢复 不手改 journal 或 head 解锁推进

07 / 本地落盘

原始状态与可读产物分开。

.reviewer/
├─ threads/<thread-id>.json　当前 thread 索引
└─ reviews/<review-id>/　评审工作区
　　├─ head.json　领域读取入口
　　├─ …　SHA-256 寻址对象与版本
　　└─ final/　可重建的 Markdown 产物

SDK 状态位于 ${XDG_STATE_HOME:-~/.local/state}/reviewer/v1/sdk/；标准账本位于同级 ledger/ledger.jsonl。原子提交后 head 指向完整版本；未提交残留对象保留，不当作当前结果。

Markdown 是可重建副本，生成失败会报告 warning，不推翻已经提交的业务状态。新旧状态根隔离；旧材料和工作区不自动迁移。
