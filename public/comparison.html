02 / 竞品对照

有重叠，主要任务不同。

“带证据”“独立检查”“人保留判断”都不是 Reviewer 独有的能力。这里比较输入、检查重点与输出，不把官网没写的功能判为“不支持”。

窄屏可横向滚动表格；选用建议由本站归纳，产品能力来自各行的官方资料（核对于 2026-10-04）。

产品 / 主要对象 官方描述的工作方式 与 Reviewer 的关系 / 选用判断
Recensa
文档检查 · 重叠较大 		检查已完成的 DOCX / PDF：内部矛盾、数字、交叉引用，也可对照自带来源与外部来源；输出问题清单、证据和检查报告。文件印记证明完整性，不认证内容正确。
官方产品说明 ↗ 		同样围绕整份文档和可查证问题。偏成品文件检查时可优先考察；Reviewer 则把任务目标的标准对齐、Owner 确认与后续复查组织在同一 Codex 流程中。
Lenz
事实与引用核验 		从单条断言或整篇草稿识别事实与引用；深核对照独立来源，返回判断和推理。草稿检查后可选择哪些断言继续深核。
官方工作方式 ↗ 		覆盖 Reviewer 置信检查中的一部分需求。重点是断言与引文时可考察；如果还要判断方案是否覆盖已确认目标，需另有任务验收标准。
Factiverse
声明识别与证据核验 		从文本、音频、视频识别声明，对照可信来源；官方场景包括媒体研究和 AI 模型审计。
官方能力与场景 ↗ 		适合考察跨媒介的信息核验需求。Reviewer 当前聚焦材料验收流程，没有已验证的音视频核验承诺。
Prelint
PR 的产品一致性 		把 PR diff 对照产品规范、架构决定与自定义规则，另一次 AI 检查筛选发现，再写入行内评论与检查摘要；新提交触发后续评审。
官方评审流程 ↗ 		也关心标准、决定和变化。代码是否按产品决定实现，可考察 Prelint；Reviewer 的主对象是方案与研究等交付材料，纯代码审查不在 V1 范围。
Patronus
AI 输出评测基础设施 		用现成或自定义 evaluator 评价模型输出，可组织数据集实验、记录结果并比较实验。
官方评测入口 ↗ · 自定义判定标准 ↗ 		可以定制质量标准，并非只能查幻觉。需要持续评测 RAG、模型或 Agent 系统时可考察；Reviewer 组织的是一份材料从标准确认到人的处置。
直接请另一位 Agent 评审
工作方法，非单一产品 		把材料和要求放进对话，请它给出意见；也能主动要求引用、标准和多轮检查，具体取决于提示与工具。 低风险快速浏览的直接替代方案。Reviewer 将确认、绑定与复查固化为流程，代价是更多步骤、等待与模型调用；尚无证据证明所有任务上都更划算。
最近的对照：Recensa 与直接请 Agent 评审

前者与材料检查本身高度重叠，后者在现有对话中即可开始。Reviewer 是否值得用，要看标准对齐与复查记录能否改善你的实际验收；不能靠功能清单替代这个判断。

03 / Reviewer 的区别

把一份材料的验收过程连起来。

  1. 先确定这次凭什么判断

    从任务、已签核上游要求和你确认过的标准出发，对齐范围、排除项、来源、深度与成本。独立检查标准的覆盖和忠实度，再由你确认冻结。

  2. 同时检查“合不合目标”和“可不可信”

    完整评审既查遗漏、逻辑和跨文档一致性，也查事实、数字、引用与结论强度。每个问题关联标准、原文和证据；设计提议与现状断言分开判断。

  3. 修改后延续同一次评审

    依据变更、标准、证据新鲜度和依赖范围决定哪些内容必须重查。保留决定记录，由你接受、要求修改或暂缓；包括首轮最多三轮。

这些是 Reviewer 的组合设计与过程约束，并非“其他工具都做不到”的声明。模型仍可能误判，证据也需要检查。查看实现与守卫边界 →

按材料和决定，选入口。

跨文档交付 / 交接包 设计、说明、已签核要求与可访问的运行证据；查各文档口径、承诺和状态是否一致。 完整评审

开工前还没讲清标准 目标、任务、上游决定；正文可尚未写出。 仅对齐标准

适合：准备签一份系统设计

“这是方案和已签核需求。请确认验收标准，检查重试策略是否矛盾、数据删除策略是否遗漏，以及‘当前已上线’是否有证据。”

有材料、上游依据和明确决定，可进入完整评审。

先换方法：只想知道服务是否正常

“帮我确认这个服务现在能用。”先实际运行、测试并看日志；文字评审无法代替这些操作。

拿到运行证据后，Reviewer 可以检查验收说明是否如实表达这些证据。

05 / 边界与投入

什么情况下不值得用？

  • 一个事实、随手浏览：直接找来源或请 Agent 给第二意见，通常不需要整套流程。
  • 错别字、排版、文风：用编辑与校对工具。它们不属于 Reviewer 的产品目标。
  • 纯代码质量、测试或安全扫描：使用相应工程工具；Reviewer 不替代单元测试、代码评审与安全验证。
  • 需要专业认证或无人承担最终决定：Reviewer 不提供合规认证，也不代替人的风险取舍。没有最终决定人，不适合启动此流程。
  • 希望团队共同审批、跨宿主直接用：本轮只适配单用户 Codex；多人协作和其他宿主不是当前已交付范围。
开始前带上这四样

材料或目标、可引用的上游要求、允许访问的证据来源、最终决定人。检查深度、联网权限和成本上限在标准对齐时确认；不用先手工准备 schema 或 digest。

认真评审会增加对齐、独立检查与复查的时间和模型调用成本。投入上限因任务而定，不预设“一份材料固定多少钱”。来源不可访问或证据不足时，应如实保留缺口。

当前产品以单用户的长篇和跨文档材料为设计中心；可处理的材料类型是范围说明，不能据此推断已经证明能降低误判率、返工率或总成本。查看已经验证与尚未验证的部分 →
