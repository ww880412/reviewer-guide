完整评审路径

两条 Loop，连接标准与材料。

查看流程与返回路径 →
LOOP 1

对齐“什么算好”

读取任务与已签核依据，核对历史口径。对新增和冲突项表态后，提案先经独立审查，再由你确认标准和方案。

  1. 起草标准与范围
  2. 独立审查覆盖与忠实度
  3. 确认并冻结
产出：冻结标准、检查方案、决定记录
LOOP 2

检查“材料达到了吗”

按单元快筛、深核与独立复核，保留证据和分歧。最终处置由你决定，修改后按影响范围复查。

  1. 拆分与分流核验
  2. 协调证据和未解项
  3. 你决定接受或修改
产出：带证据的最终页、复查记录

恢复、状态和成本记账支撑这两条 Loop，不另构成第三条产品流程。

当前影子模式呈现检查结果和处置选项，不自动生成接受建议。

A

标准与方案

检查什么、允许用哪些来源、是否联网、深核规则和成本上限，以及本次排除和假设。

B

证据与缺口

每条问题对应标准和材料位置；区分阻断、修改项、证据不足、未覆盖和已接受风险。

C

决定与复查

保留每轮处置、材料版本和依据。改了什么、重查了什么、沿用了什么，都可追溯。

为什么使用插件

让评审有连续的依据。

你关心的事 直接请 LLM 看看 Reviewer 的约束
评审标准 随提问和上下文组织 先确认标准、来源与评审方案，检查时按冻结版本执行
问题凭据 取决于单次回答质量 关联标准、原文、允许来源；结构完整不等于语义正确，仍需独立核验
独立性 可换独立对话；独立性取决于上下文与工具安排 独立上下文检查标准与关键发现，核对真实任务身份和输入绑定
修改之后 可手动提供变更与旧结论，安排复查 按变更、标准、证据新鲜度与依赖范围复查
你的决定 需要自行区分人的决定与 Agent 的建议 以原生问题卡的真实回复形成决定回执，沉默不算同意

Reviewer 仍使用模型做语义判断；软件守卫负责过程约束，无法保证模型永远正确。
